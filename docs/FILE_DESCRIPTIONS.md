# File Descriptions

This file provides a brief but thorough description of all non-ignored files in the project.

## Root Directory

- **.gitignore**: Specifies intentionally untracked files to ignore. This file is used by Git to determine which files and directories to ignore, before you make a commit. This file is crucial for keeping the repository clean and avoiding the submission of unnecessary files, such as build artifacts and local configuration files.
- **build.gradle.kts**: This is the top-level build file for the entire project. It's used to define the build configurations that apply to all modules in the project. This file hooks into the Gradle build system and is responsible for defining the plugins and dependencies that are shared across all modules. It's the entry point for the build process.
- **gradle.properties**: This file is used to configure project-wide Gradle settings, such as the JVM arguments for the Gradle daemon, and AndroidX properties. These properties are used by the Gradle build system to configure the build environment. This file is read by Gradle at the start of the build process.
- **gradlew**: The Gradle wrapper script for Unix-based systems. This script allows you to run Gradle tasks without having to install Gradle on your system. It hooks into the Gradle build system and is the recommended way to run Gradle tasks.
- **gradlew.bat**: The Gradle wrapper script for Windows. This script allows you to run Gradle tasks without having to install Gradle on your system. It hooks into the Gradle build system and is the recommended way to run Gradle tasks on Windows.
- **settings.gradle.kts**: This file is used to define the project structure, and to include the modules that are part of the project. It hooks into the Gradle build system and is responsible for defining which modules are included in the build. This file is read by Gradle at the start of the build process, before the `build.gradle.kts` files.

## App Directory

- **.gitignore**: Specifies that the `build` directory within the `app` directory should be ignored by Git. This is important to prevent build artifacts from being committed to the repository.
- **build.gradle.kts**: This is the module-level build file for the `app` module. It's used to configure the build settings for the app, including dependencies, plugins, and Android-specific settings. This file hooks into the Gradle build system and is responsible for defining the dependencies and build configurations for the app module. It's a critical file for the app's build process.
- **google-services.template.json**: This is a template file for the `google-services.json` file. It's used to configure Google services for the app. This file is used by the Google Services Gradle plugin to configure the app to use Google services, such as Firebase. It's a template file because the actual `google-services.json` file contains sensitive information and should not be committed to the repository.
- **proguard-rules.pro**: This file is used to configure ProGuard, which is a tool that shrinks, optimizes, and obfuscates your code by removing unused code and renaming classes, fields, and methods with semantically obscure names. This file is used by the R8 compiler to determine which code should be kept and which should be removed. It's an important file for reducing the size of the app and improving its performance.

## Docs Directory

- **INDEX.md**: This file is the table of contents for the documentation. It provides a list of all the documentation files and links to them. This file is the entry point for the documentation and is used to navigate to the other documentation files.
- **UI_UX.md**: This file describes the user interface and user experience of the app. It covers the OverlayService, the interactive tutorial, and the user experience for key exchange. This file is important for understanding how the user interacts with the app and how the different UI components work together. It hooks into the `screens.md` file, which describes the main screens of the app.
- **auth.md**: This file describes the different key types and password protection mechanisms in the app. This file is important for understanding the security of the app and how the different key types are used. It hooks into the `data_layer.md` file, which describes the cryptographic model of the app.
- **conduct.md**: This file outlines the code of conduct for contributors to the project. This file is important for ensuring that the project is a welcoming and inclusive environment for all contributors.
- **data_layer.md**: This file describes the data storage, cryptographic model, and key generation mechanisms of the app. This file is important for understanding how the app's data is stored and how the encryption and decryption processes work. It hooks into the `auth.md` file, which describes the different key types, and the `workflow.md` file, which explains the encryption and decryption process.
- **fauxpas.md**: This file lists common mistakes and anti-patterns to avoid when working on the codebase. This file is important for maintaining the quality of the codebase and avoiding common pitfalls.
- **misc.md**: This file contains miscellaneous information about the app that does not fit into other categories. This file is a catch-all for information that doesn't fit into the other documentation files.
- **performance.md**: This file discusses performance considerations, particularly related to the background services that power the app. This file is important for understanding how the app's performance can be improved and how the background services affect the app's performance. It hooks into the `misc.md` file, which describes the background services in more detail.
- **screens.md**: This file describes the main screens and UI components of the app. This file is important for understanding the app's UI and how the different screens are connected. It hooks into the `UI_UX.md` file, which describes the user experience of the app.
- **task_flow.md**: This file outlines the step-by-step user flows for key management, encryption, and decryption in the app. This file is important for understanding how the user is expected to use the app and how the different features work together. It hooks into the `workflow.md` file, which explains the encryption and decryption process in more detail.
- **testing.md**: This file outlines the testing strategy for the app. This file is important for understanding how the app is tested and how to contribute to the testing effort.
- **workflow.md**: This file explains the encryption and decryption process in the app. This file is important for understanding how the app's encryption and decryption processes work. It hooks into the `data_layer.md` file, which describes the cryptographic model of the app, and the `task_flow.md` file, which outlines the user flows for encryption and decryption.
